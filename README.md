# 招标文件关键条款抽取与废标风险自查工具

![version](https://img.shields.io/badge/version-v1.0.0-blue)
![python](https://img.shields.io/badge/python-3.10%2B-3776ab)
![recall](https://img.shields.io/badge/recall-100%25-brightgreen)
![precision](https://img.shields.io/badge/precision-92.5%25-green)

输入一份 60–120 页的招标文件（PDF / DOCX），3 秒输出一份 Excel 风险自查报告：
**12 类关键条款 + 红/黄/绿分级 + 原文页码 + 复核建议**。

> 状态：**v1.0.0 功能闭环**（2026-11）｜解析 → 抽取 → 分级 → 报告 → 评估 五段全通，指标达标。
> 已知未做：语料 6/20 份、DOCX 解析、演示视频。

## 解决什么问题

一份招标文件 60-120 页，中小企业投标需要人工找资格要求、保证金、工期、废标条款平均需要 45 分钟，耗费时间长。更麻烦的是遗漏"投标文件未按要求签字盖章"这类藏在第 47 页的表格里的条款导致废标。这个工具输入一份招标文件，3 秒就能给出 Excel 风险清单（12 类关键条款 + 红黄绿分级 + 原文位置 + 复核建议）。人不用再从 66 页里翻，只需要复核 3 类红色条款。

## 架构

```
data/raw/*.pdf
      │
      ├─ parse.py（PDF → 带页码的文本块）
      │      三通道：正文 / 表格 / 章节标题
      │
      ├─ rules.py（— → 12 类条款的关键词 + 章节归属）
      │
      ├─ extract.py（文本块 → 12 类命中列表，含页码/原文/置信度）
      │
      ├─ grade.py（命中列表 → 每类一个等级 + 理由）
      │
      └─ report.py（分级结果 → 4 个 sheet 的 Excel）

reports/*_风险自查报告.xlsx（概览 / 风险清单 / 全部条款 / 待复核）
```

每一层只依赖上一层的输出：换规则不用动解析，换报告不用动抽取；每一层都能单独跑、单独验。

## 12 类条款

| 代码 | 类别 | 风险含义 |
|------|------|---------|
| C01 | 项目编号/名称 | 填错即无效 |
| C02 | 预算/最高限价 | 超预算直接废标 |
| C03 | 投标保证金 | 未按时足额缴纳即废标 |
| C04 | 投标截止/开标时间 | 迟到 1 分钟即拒收 |
| C05 | 资格要求-资质 | 不满足即不合格 |
| C06 | 资格要求-业绩 | 业绩不达标即不合格 |
| C07 | 资格要求-人员 | 人员不符即不合格 |
| C08 | 评分办法 | 决定报价策略 |
| C09 | 废标条款 | 最高优先级，全部摘出 |
| C10 | 签字盖章要求 | 最高频的低级废标原因 |
| C11 | 联合体/分包 | 影响主体资格 |
| C12 | 投标文件组成 | 缺件即废标 |

## 快速开始

**环境**：Python 3.10+（开发环境 3.13.17），Windows / macOS / Linux 均可

**依赖**（4 个）：

| 包 | 用途 |
|----|------|
| pdfplumber | 读 PDF（正文 + 表格） |
| python-docx | 读 DOCX |
| pandas | 组织表格数据 |
| openpyxl | 写 Excel 报告 + 画图 |

### 1. 安装

```bash
python -m venv .venv
.\.venv\Scripts\Activate.ps1          # Windows
# source .venv/bin/activate           # macOS / Linux
pip install -r requirements.txt
```

> 国内网络建议加镜像：`pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple`
>
> Windows PowerShell 若提示「禁止运行脚本」，先执行：
> `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`

### 2. 跑起来

```bash
# 生成一份风险报告，输出到 reports/
python -m tendercheck.report "data/raw/你的招标文件.pdf"

# 只看 12 类的分级结果（不写文件，直接打印）
python -m tendercheck.grade "data/raw/你的招标文件.pdf"

# 跑量化评估（需要 data/标注表.xlsx）
python -m tendercheck.evaluate
```

> 用 `-m` 而不是 `python tendercheck/report.py`：项目是一个包，包内模块互相引用时
> 必须让 Python 从项目根目录开始找模块。

## 指标实测

在 **6 份人工标注文件 / 5 个行业（72 个判断）** 上逐类对账：

| 指标 | 实测 | 目标 | 达标 |
|------|------|------|------|
| 微平均准确率 `TP/(TP+FP)` | **92.5%**（62/67） | ≥ 85% | ✅ |
| 宏平均准确率（逐类平均） | **90.6%** | ≥ 85% | ✅ |
| 召回率 `TP/(TP+FN)` | **100.0%**（62/62） | ≥ 90% | ✅ |
| 假阳性率 `FP/(TP+FP)` | **7.5%**（5/67） | < 20% | ✅ |
| 单份文件端到端耗时 | **2.96 秒** | < 10 秒 | ✅ |
| 类别覆盖 | 12 / 12 | 12 / 12 | ✅ |
| 样本量 | 6 份 / **5 行业** | 20 份 / 5 行业 | 🚧 份数待补 |

- **9 类满分，问题集中在 3 类**：C05 资质（66.7%）、C06 业绩（60%）、C07 人员（60%）。
  "编号/预算/保证金/截止/废标/签章"这类条款措辞固定；而"资质/业绩/人员"的表述千变万化，
  且大量出现在**非资格语境**里（材料清单、评分项、产品功能、代理机构联系人）。
- **召回率 100%** 是最有价值的一条：72 个判断里该抽的 62 处全部抽到，零漏判。
- **5 个假阳性全部被降级为「中」**并进了待复核，业务员看到的确定结论里没有错误。
- **两个准确率**：微平均按全部判断合并算；宏平均是每类算一遍再平均（两者都达标，差 1.9 个点）。

> ⚠️ **样本 6 份（72 个判断），规则在部分文件上调整过，且未做调参/验证划分，指标偏乐观。**
> 语料补至 20 份后会按「15 份调参 + 5 份验证」重测，只报验证集数字。

逐类明细与 5 个假阳性的逐条分析见 [docs/评估报告.md](docs/评估报告.md)。

## 已知边界（主动说明）

- **不做 OCR**：无文本层的扫描件直接标「需 OCR」，不硬猜——工具的第一价值是可信，不是覆盖面。
- **12 类不覆盖技术参数与产品认证**（CCC 认证、节能清单、检测报告），需业务员结合采购需求章节人工核对。
- **部分文件不含招标公告**：建设工程电子标常把公告放在交易平台，文件内只留一行「公告见 XX 平台」。
  此时报告「概览」会显示**公告章节为空**并给出明确提示，截止时间等需到平台确认——**不会猜一个时间填进去**。
- 规则是「关键词 + 章节定位」，不是语义模型，换个行业的表述可能需要补词典。

标注过程中发现的更多规则边界与真实文件怪象，见 [docs/观察记录.md](docs/观察记录.md)。

## 踩坑记录

**① 一句话被 PDF 按视觉行切断**

- 现象：封面标题被切成「…设备及北」+「校区监控扩容项目」，跨行的长句整句匹配永远搜不到
- 根因：PDF 里的换行是排版结果，不代表语义上的句子边界
- 解法：规则匹配前拼接同页相邻行，或匹配时把换行视作可跳过

**② 表格抽出来的列是错位的**

- 现象：SEC-01 第 25 页「分值构成」表，正文流抽出来是
  `分值构成价格部分：30分（总分100商务部分：15分分）技术部分：55分`——列被交错拼接
- 根因：表格里的文字是按坐标绝对定位的，按阅读顺序抽取会把不同列拼到同一行
- 解法：表格单独走 `extract_tables()` 通道按行列重组（66 页抽出 131 行表格，评分表、资格审查表、签章要求都在里面）

**③ 章节标题识别的假阳性高达 60%**

- 现象：正则 `^第X章` 在 SEC-01 命中 26 处、EDU-01 命中 43 处，而真实标题只有 10 个和 11 个
- 根因：噪音来自三处——目录行（标题 + 省略号 + 页码）、重复的目录页、页眉残留（孤立的「第二节」）
- 解法：三条上下文过滤（含 `..` 丢弃 / 长度 < 6 丢弃 / 同页出现 ≥3 个候选视为目录页整页丢弃）→ 26→10、43→11

**④ 工具重复了人踩过的坑**

- 现象：EDU-01 上 C07 报出 8 条「人员要求」，首条是 `项目负责人：任丽荟`
- 根因：这个名字是**采购代理机构的联系人**；我人工标注时也差点标错，把它记进了 `docs/观察记录.md`
- 解法：置信度分级——命中不在「资格要求」章节里就降为「中」，进待复核而不是直接输出结论

**⑤ 在调过参的文件上评估，指标虚高 20 个点**

- 现象：针对 SEC-01 调完关键词后，SEC-01 准确率 100%；换到没调过的 EDU-01 掉到 81.8%
- 根因：假阳性没有消失，只是搬了家——规则是看着数据调的，换一份数据就露馅（过拟合）
- 解法：语料补到 20 份后按「15 份调参 + 5 份验证」重测，只报验证集数字；当前指标已标注「偏乐观」

**⑥ 中文路径让 OpenSSL 读不了证书**

- 现象：`git push` 报 `error adding trust anchors from file`，但浏览器能正常打开 GitHub
- 根因：项目路径含中文（`D:\文档\...`），git 内置的 OpenSSL 用 ANSI 接口读文件，读不到中文路径下的 CA 证书
- 解法：把 CA 证书复制到纯 ASCII 路径，再用 `http.sslCAInfo` 指过去

> 这六个坑不是想象出来的，每一个都在两份真实招标文件上真踩过。

