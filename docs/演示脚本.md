# 3 分钟演示脚本

> 用途：线上面试直接播放录屏；或现场演示时照着讲。
> 结构按手册 2.8：**30 秒痛点 → 60 秒方法 → 60 秒难点 → 30 秒取舍**。

---

## 录屏前的准备（5 分钟，别录的时候才找）

| 准备项 | 具体动作 |
|--------|---------|
| 终端清屏 | 打开 PowerShell，`cls`，确保命令行是空的 |
| 目录就位 | `cd "D:\文档\deepseek-harness\object-findworks\projects\tender-check"` |
| 环境变量 | 先跑那一行 cd + PATH + GIT_CONFIG_GLOBAL（否则 git 命令会报错，但录屏里用不到 git） |
| 关掉无关窗口 | 特别是聊天窗口、浏览器标签、任何 AI 对话界面 |
| 报告目录清空 | 删掉 `reports\` 里的旧文件，演示时"从无到有"更有冲击力 |
| 录屏工具 | `Win + Alt + R`（Xbox 录制当前窗口）或 OBS；**只录应用窗口，别录整个桌面** |

## 00:00–00:30 讲痛点（30 秒）

**画面**：打开一份招标文件的 PDF，停在目录页，鼠标滚一下页面。

**台词**：

> "中小企业投一个标，先要读这么一份 60 到 120 页的招标文件。
> 资格要求、保证金、截止时间、废标条款散在几十个章节里，人工找一遍平均 45 分钟。
> 最麻烦的是漏——比如'投标文件未按要求签字盖章'这条，往往藏在第 47 页的表格里。
> 漏一条，前面几天全白做。"

**要点**：这一段**不要讲技术**，只讲人的痛。让面试官先在脑子里看到那个场景。

---

## 00:30–01:30 讲方法（60 秒）

**画面**：切到 README 的架构图那一段（或直接讲，不切屏）。

**台词**：

> "我没有把文件直接丢给大模型去猜，因为业务员要的是**可核对**——每条结论必须能点回原文第几页。
>
> 所以我做的是三步确定性流程：
> 第一步，PDF 解析成带页码的文本块，**表格单独走一条通道**——因为 80% 的关键条款都在表格里，
> 按正文流抽取会把列拼错行。
> 第二步，用 12 类条款的规则去匹配，但**不是全文搜关键词**，而是先定位章节：
> 比如'人员要求'只在'资格要求'那一章里找，这样就不会把代理机构的联系人也当成人员要求。
> 第三步，给每条结果打置信度：命中在正确章节算高，只命中关键词算中。
> **中低置信度不直接输出结论，而是进'待复核'让人看一眼。**"

**要点**：讲"为什么这么设计"，不要讲"我用了什么库"。库谁都会用，设计取舍才是你的。

---

## 01:30–02:30 讲一个难点（60 秒）★ 这段最重要

**画面**：终端里跑下面这条命令，等 2 秒出结果。

```powershell
.\.venv\Scripts\python.exe -m tendercheck.report "data\raw\SEC-01_新乡职业技术学院二期安防监控设备及北校区监控扩容项目.pdf"
```

然后**双击打开** `reports\` 下新生成的 Excel，翻到「概览」和「风险清单」。

**台词**：

> "说一个我觉得最有意思的坑。
>
> 我一开始拿这两份文件调规则，调完在 SEC-01 上准确率 100%，我挺得意。
> 然后换成另一份没调过的文件测——掉到 81.8%。
>
> 我去看错在哪，发现工具报'人员要求'，命中的是『项目负责人：任丽荟』——
> 这个名字是**采购代理机构的联系人**，跟投标人没有关系。
> 而我人工标注的时候，也差点在这一处标错。
>
> 也就是说，**人踩过的坑，代码会再踩一遍**。
> 所以我没去删那个关键词（删了别的文件就漏），而是做了置信度分级——
> 这种命中不在资格章节里，自动降成'中'，进待复核，不冒充确定结论。"

**要点**：这是整个演示的高潮。它同时证明了你**会测**、**会分析错误**、**会做取舍**。

---

## 02:30–03:00 讲取舍（30 秒）

**画面**：停在 Excel 的「待复核」sheet。

**台词**：

> "最后说三个我明确没做的事。
>
> 第一，**不做 OCR**——扫描件没有文本层，我宁可标'需 OCR'，也不给一个不准的结果。
> 第二，**不覆盖技术参数和产品认证**——CCC、节能清单这些属于采购需求，不在 12 类里，
> 我在 README 和说明书里都写明了。
> 第三，**不做公司资质匹配**——那需要客户输入自己的资质，现在这版先做不需要外部输入的部分。
>
> 我觉得工具的价值首先是可信，其次才是覆盖率。"

**要点**：能说清"我为什么没做什么"，比说"我做了什么"更像做过真实项目的人（手册 1.8 原话）。
